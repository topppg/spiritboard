# Promotional media

- `../dashboard.png`: the current dashboard, 1440 pixels wide, with an expanded session
  showing **open in Ghostty** and **let it rest** together. Invented sessions across six
  harnesses show concrete SWE work: keyset pagination, listener leaks, retry races,
  migration reviews, and delegated regression tests.
- `../session-open.png`: a closer view of that session and both actions, captured from
  the real UI after filtering to its title. The README caption identifies the synthetic data.
- `demo.gif`: a 10-second looping capture of the same dashboard, 1280×800.
  It demonstrates the **needs you** filter, session actions, **let it rest**, and task search.
  The full-board capture and tour retain the app's synthetic-demo banner.
- `social-preview.png`: the 1280×640 GitHub social card. `social-preview.html` is its source.
  It reuses the native orbital mark, bundled Space fonts, and the refreshed synthetic
  `docs/dashboard.png`.
- `workspace-overview.png`: an AI-generated explanatory composition based on the
  dashboard above. Four Ghostty panes and one Claude Desktop Code session use the
  same invented task names as the board. This illustrates the relationship between
  the apps; the terminal and Claude windows are mockups, not captured applications.
- `workspace-overview.mp4` and `workspace-overview.gif`: a silent animated tour of
  that composition, highlighting matching sessions. This is an illustration, not a
  screen recording or a demonstration of live monitoring speed. The existing README
  screenshot and recorded interaction tour are kept separately.

## Rebuild

From the repository root, with Node.js, `uv`, and an isolated Playwright installation:

```bash
capture_tools="$(mktemp -d)"
npm install --prefix "$capture_tools" playwright@1.62.1
"$capture_tools/node_modules/.bin/playwright" install chromium
NODE_PATH="$capture_tools/node_modules" uv run --with pillow==13.0.0 python scripts/capture_demo.py
```

If using an existing browser binary, set `CHROMIUM_EXECUTABLE_PATH` to its full path.
If Node is not on PATH, pass `--node /absolute/path/to/node` to the capture script.
The capture tools are not app dependencies and are never added to the lockfile.

The script uses a temporary SQLite store, random local ingestion token, and invented
native-session observations. It never discovers native accounts, reads transcripts or
saved credentials, or configures a summary provider. The dashboard capture blocks requests outside
the temporary loopback collector. All session names, activity, and approval text are
invented. Temporary events and frames disappear after capture; no real agent is started.

Profiles, liveness, app targets, projects, requests, and replies are all synthetic. The
capture-only collector returns harmless app targets with no activation commands so the
real UI can display its **open** buttons without inspecting or launching any app. Browser
capture also rejects non-GET requests. The script seeds ten minutes of invented observation
history with a fixed random seed: independent bursts, uneven peaks, jittered timestamps,
and quiet gaps. It does not record real activity. Summaries remain off.

Fixtures follow native adapter output: terminal/editor names appear only in focus targets,
not desktop-app badges. Claude and Pi questions end in **your turn**; DeepSeek approvals
and Grok prompts can show **needs you**. Pi sessions have no inferred parent, Codex turn
completion stays idle, and Grok has no project or known process liveness.

Capture assertions require both session actions to be visible and enabled, and check that
parents with running workers say **running**, never **your turn**. The expanded finished-turn
session has no running children and legitimately offers **let it rest**.
Real-browser geometry checks also require status symbols and text to align at the same
tree depth. Subagents retain the product's normal indentation.

Fifty sampled dashboard frames play at 200 ms each (5 fps), totaling exactly 10 seconds.
This is an interaction demonstration, not a real-time performance measurement.
The script checks the GIF dimensions, duration, and 5 MB size limit before succeeding.
Capture timestamps and internal journal IDs vary, so regenerated bytes may differ.

The social card is a branded composition of the refreshed example screenshot, not a
new dashboard UI. Upload `social-preview.png` under GitHub repository **Settings →
General → Social preview**. Committing it alone does not activate the preview.

## Workspace illustration

The built-in imagegen tool generated `workspace-overview.png` from the synthetic
`docs/dashboard.png` reference. The full generation prompt is saved in
`workspace-overview-prompt.txt`. No real terminals, app conversations, profiles or
credentials were used. The matching sessions are:

| Window | Session | Agent |
| --- | --- | --- |
| Ghostty | Orders cursor pagination | Codex |
| Ghostty | WebSocket listener leak | Claude Code |
| Ghostty | Flaky upload retry test | opencode |
| Ghostty | CLI JSON output | Pi |
| Claude Desktop Code | Invoice currency backfill | Claude |

To render the 18-second animation with an installed FFmpeg:

```bash
uv run python scripts/render_workspace_video.py --ffmpeg /absolute/path/to/ffmpeg
```

For an isolated FFmpeg binary without a system installation:

```bash
workspace_ffmpeg="$(uv run --with imageio-ffmpeg python -c 'import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())')"
uv run python scripts/render_workspace_video.py --ffmpeg "$workspace_ffmpeg"
```

Pass `--font /absolute/path/to/font.ttf` to choose the phase headline font. The
renderer uses only the saved illustration and local FFmpeg; it never reads agent
sessions or launches another app. The MP4 is 1600×1000 at 24 fps, with H.264 video
and no audio. The looping GIF is 1200×750 at 8 fps and stays below 5 MB. The renderer
decodes both outputs and verifies frame counts and duration before succeeding.
